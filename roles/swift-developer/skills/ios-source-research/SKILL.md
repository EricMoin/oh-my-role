# Resolve one disputed fact

1. State the decision and the competing outcomes. For example, will an Observation-based screen build and update on the app's minimum supported iOS version? Identify the scheme, deployment target, Xcode and SDK, Swift language mode and relevant package pin. For a command-line question inspect the installed tool's help.
2. For a library, SDK, API, CLI or service question, resolve the library in Context7 with its name and the full question. Select a relevant authoritative ID, then query it for the behavior in context. A supplied exact ID can go straight to the query. For general design, local business logic and code review, use the project evidence directly unless an API fact needs research.
3. Follow the returned source URL to the symbol, availability declaration, migration guide or release note. Check platform and version. A page for macOS, a beta SDK or a proposal awaiting implementation can describe a different contract. Swift language mode, the compiler version, package tools version and the installed OS answer different questions. [Swift Evolution](https://www.swift.org/swift-evolution/) · [Xcode release notes](https://developer.apple.com/documentation/xcode-release-notes)
4. Check what this target actually compiles against. Use Quick Help, Jump to Definition, the installed SDK's public headers or generated Swift interfaces. Inspect `Package.resolved` used by this build and the matching checkout before citing Swift package implementation. Use the library's release tag or commit and cite file and symbol. Keep project locks intact. The open-source Swift toolchain is useful for language behavior. Framework interfaces reveal public signatures and availability. UIKit and SwiftUI implementation internals often require a documented contract or a focused black-box observation.
5. When Context7 lacks coverage or sources disagree, consult Apple DocC, WWDC with its session year, a Swift release note, or the package maintainer's source at the resolved revision. Test the disputed behavior on a matching destination when observation is decisive. Describe when and where it happened. A successful compile establishes availability at that build configuration, while a framework's runtime behavior can vary across OS releases.

When local Apple guidance would settle a framework-design question, Xcode 27 introduced exportable skills. On a host that supports it, inspect `xcrun agent skills export --help` and export to a fresh temporary directory using the supported output option. Read the one specialist page that matches the decision. Check the app's deployment range before applying a release-specific suggestion. Existing docs and SDK interfaces remain usable on hosts without skill export. [Apple's SwiftUI skills](https://developer.apple.com/videos/play/wwdc2026/269/) · [Apple's UIKit modernization skill](https://developer.apple.com/videos/play/wwdc2026/278/)

Return the question, verified scope, finding and source (URL or local file, symbol and revision), then state its implication for the change. Mark any inference. A production article offers a hypothesis to measure locally. Stop when further investigation would leave the decision unchanged.
