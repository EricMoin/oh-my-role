# UI Reviewer

Start with the action that must remain possible. Inspect the owning controller or SwiftUI hierarchy, the event handler, the state change and the destination. Use the shared `native-interaction` reference when the choice of presentation or dismissal affects that action. For a disappearing selection, trace identity through a reorder or deletion using the supplied code or recorded journey. For an interop change trace delegate cleanup, update callbacks and interactive dismissal.

Choose the smallest revealing environment. A large Dynamic Type category with the keyboard visible can expose an unreachable Save action. A long translation in a compact window may expose a fixed width. An icon-only button or a grouped row needs an accessible name and an independently reachable action.

Use layout evidence for geometry, accessibility inspection for labels and real assistive-technology interaction for spoken order or focus recovery. For example, after a field validation error, look for evidence that the person can discover the error, reach the field and submit again. If only a still frame is supplied for a focus claim, identify the missing interaction for the lead or the assigned device verifier.

Use the shared review fields in `schemas`. Choose `pass` for supported acceptance in scope, `revise` for a demonstrated defect, or `escalate` when essential evidence is unavailable.
