# Visual coherence and task-shaped interfaces

Use for new visual directions, redesigns, and requests to remove a generic or bloated product feel. These are decision aids, not a universal skin or a mandate to simplify. Existing brand requirements and explicit user choices take precedence. Preserve successful color, composition, richness, and interaction while correcting the specific defect.

## Explicit rejected treatments

These defaults apply to every visual task, including small edits; they are repeated in the parent and worker prompts so reference loading cannot bypass them.

- `高效 · 智能 · 安全` is not a default heading or subtitle. Write the actual promise or arrange independently meaningful fields with layout. Do not exchange the dots for `|`, `/`, or long dashes. Literal supplied names and technical notation remain intact.
- A dark or colored stripe down the side of a card/callout is not hierarchy. Remove the strip and, where unnecessary, the enclosing card; use a heading, normal spacing, or a real status label. The same rule covers inset shadows, pseudo-elements, and narrow background blocks.
- An undirected mix of colored surfaces and accent families is not identity, but reducing hue count is not a remedy by itself. Use the full color system deliberately: select the intended relationship, assign stable roles, and balance emphasis in the actual composition. Colored surfaces and multiple accents can be essential to the design. Compare their application, not just an isolated swatch list.

Only exact user/project requirements justify exceptions. Do not use this rule to remove a genuine selection indicator, a useful independent item card, brand-mandated colors, or data encoding. Record what was inspected and the specific exception rather than silently waiving the rule.

## Decide what deserves to exist

Before choosing components, identify the primary work object and the action or reading sequence. A receipt editor needs the receipt and editing controls; it does not automatically need a dashboard around them. A research archive needs ways to find and inspect material; a promotional hero can obstruct that purpose.

In Design State's Direction, record a short rationale covering:

- The task-bearing structure and appropriate density.
- The content or asset that supplies the visual identity.
- The interface elements deliberately omitted, and any existing conventions retained.

Keep this proportional to scope. For a small edit, a sentence is enough; do not turn it into a separate approval gate. If identity is unknown, choose a modest provisional treatment and label the assumption instead of inventing a brand story.

## Select structure before styling

| User work | A useful starting structure | Evidence needed before adding more |
|---|---|---|
| Edit one object | Object, fields, nearby actions | A sidebar needs real destinations; a summary needs a decision it helps |
| Compare many records | Aligned rows or a table, relevant filters, detail access | Cards must improve the comparison rather than scatter comparable values |
| Read an article or reference | Reading column, meaningful headings, contextual navigation | A content summary must reduce search or orientation effort |
| Browse visual items | Images with useful captions and selection controls | Card surfaces must communicate grouping or interaction |
| Explain or sell a product | Real product evidence, clear explanation, relevant action | Metrics, endorsements, and feature sections require actual content and purpose |

These are hypotheses, not mandatory layouts. Keep existing structures that support the task. An actual SaaS product can use these same principles; the problem is unearned interface, not its business model.

## Inspect the cost of each interface element

- **Navigation:** a persistent rail consumes width and attention. Keep it when users switch between real areas; avoid invented destinations or an extra dashboard hub for a single workflow.
- **Summaries:** a number deserves a prominent tile when it changes a decision. Do not promote record counts, greetings, or status restatements into a KPI row to fill the viewport.
- **Containers:** distinguish an independent object or interaction from a mere paragraph. For the latter, try normal flow, alignment, or a divider. Preserve containment when it explains selection, drag boundaries, a distinct surface, or an independent action.
- **Text and controls:** avoid saying the same thing in a breadcrumb, title, subtitle, badge, and empty state. Keep labels, units, errors, and instructions necessary for comprehension and accessibility.
- **Empty space:** remove wrappers before shrinking text or hit areas. On professional tools, preserve scan speed and useful simultaneous information; on reading surfaces, preserve comfortable measure and rhythm.

## Derive the visual voice

Choose typography for the actual language, content length, and rendering environment. Test Chinese/mixed-script text when relevant; a Latin display font is not a complete Chinese typographic system. Keep a working project font unless changing it solves a design problem.

Color, surface treatment, and motion should have a role in the selected direction. A product-specific diagram, photograph, content arrangement, or typographic treatment can carry identity without decorating every element. Neither rounded cards nor square corners, blue nor beige, light nor dark, are proof of quality. An absence of user preference does not justify applying one familiar palette to every project.

## Refinement and acceptance

During the existing artifact inspection pass, compare the result with the brief and, for an optimization, the baseline. Fix the cause: incorrect role usage may need remapping, weak grouping may need layout adjustment, missing emphasis may need richer color or typography, and actual redundancy may need removal. Preserve useful features, visual identity, and established component relationships. Retain complete reusable token families even when the current screen does not use them all.

Review the rendered result against the task and Direction. Where rendering is unavailable, report the narrower inspection scope. An apparent template is a lead for investigation, not a verdict. Describe the element, the cost to the user's task or agreed visual brief, and the smallest correction. Do not demand new decoration to make a quiet design “more designed.”

Calibration examples:

- A small timer should expose time and controls without invented reports or account areas.
- An operations console can retain compact tables, persistent filters, and necessary navigation; deleting them for empty space is a regression.
- A photo collection can retain image cards when they support browsing and selection.
- A request for expressive maximalism can use rich visual treatment; avoid unrelated features without diluting its intended intensity.
- A product with complementary brand colors must retain that relationship when correcting a single illegible badge; fix its shade or foreground instead of neutralizing the page.
- A multi-series chart must keep distinguishable categories and a stable legend; a one-accent palette is not a quality requirement.
- A successful card-based image browser needs corrections to defective styling, not automatic conversion to a flat text list.
