# Domain routing

Read references/departments.md, generated from departments.json. Do not maintain
another department table here. Prefer the explicit subtask domain; otherwise use
the registry scope and keywords with repository context. Classify by intended effect,
not incidental words such as class, model or test in a filename.

Known domains bind directly to the registered worker. Unknown or genuinely mixed
work uses Jinyiwei inline, or returns to planning if it cannot be one coherent task.
Never split work behind the orchestrator's dependency graph. Forward the complete
contract, research flag, verification plan and authorization when routing.

A fallback child uses its own graph. Do not reuse a graph whose parent is waiting
for you. Runtime scheduling, approval and result transport follow graph-protocol.md.
