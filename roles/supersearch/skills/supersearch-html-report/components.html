HTML 组件参考

本页展示可独立选用的排版与交互。报告应先有自己的问题、证据和论述，再选择需要的组件；这里的章节不是报告目录，也没有需要逐项填写的内容。

可以修改布局、样式和脚本，也可以只取段落与引用样式。若保留搜索或目录定位，需同步维护其元素和选择器。页面右上角提供搜索与主题切换演示。

论述与直接引用

一个论述段落应把发现、理由和对读者的影响连接起来。需要核查的表述旁边放置能直达原文的链接，例如 来源标题 · 对应小节（示例链接）。同一来源支持的连续段落不必每句重复链接，但来源变化时要清楚标出。

技术名词用于保留关键区别，因果和取舍则用普通语言解释。max_attempts 这样的精确标识可以保留；段落需要继续说明它限制了什么、在什么条件下起作用，而非用更多术语代替解释。

上面的链接是演示地址，不支持本页的任何研究结论。实际报告只使用已检查的来源和已确认的定位信息。

原文摘录

只有原文措辞本身重要时才选用引用块。短句也可以直接放进段落；不必每节安排一段引文。

这是引用排版示例，并非从真实来源摘录的文字。

— 作者或机构 · 文档标题（示例链接）

真实摘录应忠于原文，并在附近解释它证明了什么。可见来源链接方便直接核查；仅有 cite 属性不能替代链接。译文和省略应明确标识。

补充说明

说明块适合承载读者确实需要单独注意的信息。正常论述不必拆成大量提示框，也不必把正文结论再重复一遍。

若一项结论只适用于特定版本，应在该结论附近写明版本；总体证据评估集中放在报告结尾。

配图与图注

图片应帮助解释机制、比较或观察结果。有候选图片并不意味着必须使用。这里仅展示标记写法，没有加载演示图片。

<figure class="figure">
  <img src="https://example.org/inspected-diagram.png"
       alt="描述图中与论述有关的结构或差异">
  <figcaption>解释此图与论点的关系。来源：
    <a href="https://example.org/source-page">机构 · 页面标题</a>
  </figcaption>
</figure>

实际配图需来自已检查的来源，使用外部 http(s) 图片直链，并在图注提供来源归属。同一论点确需并列图片时，可以选用 .figure-grid，无需为其他章节凑图。

来源索引与结尾说明

来源索引供读者集中浏览；正文里的引用仍直接打开来源。下面两项是索引样式演示，不是证据清单。

  1. 来源标题（示例链接） — 实际报告可附发布机构、日期或版本，帮助读者识别材料。
  2. 文档标题（示例链接） — 同一来源在索引中合并，正文按需要链接不同段落。

证据与局限

在实际报告末尾，用一处说明概括证据覆盖、时效和未解决的问题，并指出哪些结论会受到影响。不要逐节复制这一组件，也不要将此演示文字带入报告。
